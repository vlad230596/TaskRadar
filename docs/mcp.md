# MCP: доступ для агентов

TaskRadar отдаёт задачи кодинг-агентам (Claude Code и другим MCP-клиентам) по
протоколу MCP: агент читает проекты, задачи, заметки и песочницу, меняет
статус и текст задач. Новые задачи, цели и пункты чек-листа агент добавляет
только по прямой просьбе владельца — ни свой план работы, ни follow-up'ы он в
TaskRadar не пишет. Удалять, архивировать и переносить в песочницу через MCP
нельзя.

## Подключение

1. В приложении: **Настройки → AI → Доступ для агентов (MCP) → Создать токен**.
   Токен показывается один раз, вместе с готовой командой.
2. Вставить команду в терминал:

   ```bash
   claude mcp add --transport http taskradar https://<хост>/mcp \
     --header "Authorization: Bearer trk_..."
   ```

   `<хост>` — тот же адрес, что у API приложения. Флаг `--scope user` сделает
   сервер доступным во всех проектах, а не только в текущем каталоге.
3. Проверка: `claude mcp list` (taskradar — connected), затем в сессии
   «покажи открытые задачи проекта TaskRadar».

Отозвать токен — там же, кнопкой на строке токена: следующий же запрос с ним
получит 401. Отключённый пользователь (`npm run user:disable`) теряет и
токены.

## Инструменты

| Инструмент | Что делает |
|---|---|
| `list_projects` | проекты (без архивных, если не `includeArchived`), скоуп, счётчики задач по статусам, число заметок, категории с id, `rhythm` у проектов с ритмом |
| `list_tasks` | задачи в порядке проекта; фильтры `projectId`, `status[]`, `categoryId`, `query`, `limit` (200). `current: true` — первая открытая; описания длиннее 300 символов обрезаны |
| `get_task` | одна задача целиком: описание, категория, дата, проект, журнал статусов, `doneAt` у закрытой |
| `list_today` | день владельца: «Сегодня» (открытые с сегодняшней датой, сначала со временем), закрытые сегодня, хвост «С прошлых дней»; `tzOffsetMinutes` (по умолчанию UTC) |
| `list_done` | закрытые задачи, свежие сверху, с `doneAt` и проектом; `limit` (50), `before` для следующей страницы; возвращённые («Вернуть») сюда не попадают |
| `list_reviews` | записи еженедельных пересмотров: период, закрыто всего и по проектам, достигнутые цели, итог |
| `list_ideas` / `list_notes` | идеи (бывшие заметки) проекта целиком, с целями, при которых они лежат; два имени — один инструмент |
| `list_inbox` | песочница: необработанные строки пользователя |
| `search` | подстрока по задачам, заметкам и песочнице |
| `create_task` | новая задача в конец проекта (`title`, `description`, `status`, `categoryId`, дата `remindAt` `YYYY-MM-DD`, время `remindTime` `HH:MM`) |
| `update_task` | статус / заголовок / описание / категория / дата и время / чек-лист / место; `null` очищает поле; `inWorkingSet` (+ `workingSetContourId`) — рабочий набор контура |
| `list_contours` | контуры: слоты (занято/всего), окно, расписание; ручной выбор активного |
| `list_goals` | цели по контуру и порядку; фильтры `state[]` (`slot`, `bench`, `achieved`; по умолчанию без достигнутых), `contourId`; следующий шаг и прогресс |
| `get_goal` | цель целиком: все задачи в её порядке и идеи |
| `create_goal` | новая цель (в контур по умолчанию, если не указан); `slot: true` — сразу в слот |
| `update_goal` | поля цели и действие `slot` / `bench` / `extend` / `achieve` / `reopen`; занятые слоты — ошибка `409 slots_full` |
| `link_goal_task` / `unlink_goal_task` | связать задачу с целью (в конец списка цели) / убрать связь |

`list_tasks` и `get_task` отдают у задачи `goals` — не достигнутые цели, которым
она служит (корона), и `workingSetContourId` для задач из рабочего набора.
Цели и контуры — `design/goals-ideas-contract.md`.

**Дата задачи** (`remindAt` + необязательное `remindTime`) — день, когда
владелец займётся задачей; время — только там, где важен момент (пуш приходит
только у задач со временем). Задачи с датой дальше горизонта владельца
(«Позже», по умолчанию 10 дней) не бывают `current` и следующим шагом цели.
Дату, как и всё остальное, агент ставит только по просьбе владельца.
«Сегодня», «Сделано», ритм и пересмотр — `design/today-history-contract.md`.

Статусы: `pending` (открыта), `blocked` (ждёт), `done`. Смена статуса пишется в
журнал задачи, `done` убирает задачу из рабочего набора — ровно как с
телефона: запись идёт через те же роуты (`PATCH /tasks/:id`,
`POST /projects/:id/tasks`). Телефон увидит изменения при следующей загрузке
списка (живого push-канала в приложении нет).

## Как устроено

- `POST /mcp` — Streamable HTTP без сессий (`enableJsonResponse`): каждый
  запрос — один JSON-RPC обмен. `GET`/`DELETE /mcp` отвечают 405.
- Токен: `trk_` + 256 бит; в базе (`agent_tokens`) только SHA-256, префикс для
  списка, `lastUsedAt` (не чаще раза в минуту), `revokedAt`.
- Токен открывает **только** `/mcp`. Обычный API его не принимает (это не
  JWT), а `/mcp` не принимает JWT. Управление токенами
  (`GET/POST /agent-tokens`, `DELETE /agent-tokens/:id`) — только с обычной
  сессией приложения.
- Тексты пользователя возвращаются как значения JSON; в инструкциях сервера
  агенту сказано считать их данными, а не командами.

Код: `backend/src/routes/mcp.ts`, `backend/src/mcp/taskradarMcp.ts`,
`backend/src/lib/agentTokens.ts`, `backend/src/routes/agentTokens.ts`; экран —
`app/lib/screens/agent_access_screen.dart`. Деплой — `DEPLOYMENT.md`, раздел
«MCP-эндпоинт».
