# MCP: доступ для агентов

TaskRadar отдаёт задачи кодинг-агентам (Claude Code и другим MCP-клиентам) по
протоколу MCP: агент читает проекты, задачи, заметки и песочницу, меняет
статус и текст задач и добавляет новые («проверить фикс X»). Удалять,
архивировать и переносить в песочницу через MCP нельзя.

## Подключение

1. В приложении: **Настройки → AI → Доступ для агентов (MCP) → Создать токен**.
   Токен показывается один раз, вместе с готовой командой.
2. Вставить команду в терминал:

   ```bash
   claude mcp add --transport http taskradar https://<хост>/mcp \
     --header "Authorization: Bearer trk_..."
   ```

   `<хост>` — тот же адрес, что у API приложения. Флаг `--scope user` сделает
   сервер доступным во всех проектах, а не только в текущем каталоге.
3. Проверка: `claude mcp list` (taskradar — connected), затем в сессии
   «покажи открытые задачи проекта TaskRadar».

Отозвать токен — там же, кнопкой на строке токена: следующий же запрос с ним
получит 401. Отключённый пользователь (`npm run user:disable`) теряет и
токены.

## Инструменты

| Инструмент | Что делает |
|---|---|
| `list_projects` | проекты (без архивных, если не `includeArchived`), скоуп, счётчики задач по статусам, число заметок, категории с id |
| `list_tasks` | задачи в порядке проекта; фильтры `projectId`, `status[]`, `categoryId`, `query`, `limit` (200). `current: true` — первая открытая; описания длиннее 300 символов обрезаны |
| `get_task` | одна задача целиком: описание, категория, напоминание, проект, журнал статусов |
| `list_notes` | заметки проекта целиком |
| `list_inbox` | песочница: необработанные строки пользователя |
| `search` | подстрока по задачам, заметкам и песочнице |
| `create_task` | новая задача в конец проекта (`title`, `description`, `status`, `categoryId`, `remindAt` `YYYY-MM-DD`, `remindTime` `HH:MM`) |
| `update_task` | статус / заголовок / описание / категория / напоминание; `null` очищает поле |

Статусы: `pending` (открыта), `blocked` (ждёт), `done`. Смена статуса пишется в
журнал задачи, `done` убирает задачу из рабочего набора — ровно как с
телефона: запись идёт через те же роуты (`PATCH /tasks/:id`,
`POST /projects/:id/tasks`). Телефон увидит изменения при следующей загрузке
списка (живого push-канала в приложении нет).

## Как устроено

- `POST /mcp` — Streamable HTTP без сессий (`enableJsonResponse`): каждый
  запрос — один JSON-RPC обмен. `GET`/`DELETE /mcp` отвечают 405.
- Токен: `trk_` + 256 бит; в базе (`agent_tokens`) только SHA-256, префикс для
  списка, `lastUsedAt` (не чаще раза в минуту), `revokedAt`.
- Токен открывает **только** `/mcp`. Обычный API его не принимает (это не
  JWT), а `/mcp` не принимает JWT. Управление токенами
  (`GET/POST /agent-tokens`, `DELETE /agent-tokens/:id`) — только с обычной
  сессией приложения.
- Тексты пользователя возвращаются как значения JSON; в инструкциях сервера
  агенту сказано считать их данными, а не командами.
