# TaskRadar — единый редактор задачи: спецификация

Статус: проект, 11.11.2026. Заменяет «Новая задача» (`TaskScreen.draft`) и
«Задача» (`TaskScreen`) одним экраном. Вносит в него чек-лист, вложения-картинки,
ссылки и напоминание по месту.

## Зачем

Владелец: «создание и редактирование — два разных экрана, а должен быть один,
где можно и надиктовать, и поправить руками. Напоминание, теги времени и прочее —
сразу при создании, а не „создай, открой, допиши“». И: «по ощущению — как экран
после диктовки: приятно и драйвово, а не скучно, как сейчас».

Что сейчас (по коду):

- `app/lib/screens/task_screen.dart` — один класс, но два разных лица:
  `_draftScaffold()` показывает только текст, описание и категорию; статус,
  напоминание, «в работу», история — лишь у существующей задачи
  («ничего, что было бы ложью о строке, которой ещё нет»). Отсюда «создай,
  потом открой».
- Вход в создание: кнопка «+ Задача» внизу списка проекта
  (`widgets/task_list.dart`, `AppRoutes.openNewTask`) и микрофон проекта →
  `DictationScreen` с `ProjectDestination` → задача создаётся прямо из экрана
  разбора (`_createTask`, с напоминанием из ответа AI).
- Экран разбора диктовки (`dictation_screen.dart` `_resultView`) — то, что
  нравится: тёмный фон `voiceBackground`, заголовок 22/600, описание 17,
  подписи капсом (`TidyLabel`), обведённые плашки `voiceLine`, плашка
  напоминания с крестиком, крупная белая кнопка.

## 1. Экран: один виджет, два режима, две высоты

`TaskEditor` (новый файл `screens/task_editor_screen.dart`, заменяет
`task_screen.dart`). Параметры: `projectId`, `taskId?` (null — новая),
`prefill?` (`TaskDraft`: текст, описание, напоминание, parseId — для передачи
из диктовки), `initialHeight` (`compact | full`).

| | Новая (`taskId == null`) | Существующая |
|---|---|---|
| Шапка | «Новая задача», чип проекта — **переключаемый** (как `_DestinationChip`) | «Задача», чип проекта не переключается (задача не меняет проект — комментарий в `schema.prisma`) |
| Статус | сегмент **Открыта / Блокер** (сделанную не создают) | Открыта / Блокер / Сделано, как сейчас `_StatusSegment` |
| «Взять в работу» | нет (фокус не идёт через outbox) | как сейчас `FocusToggleButton` |
| Напоминание, место, категория, чек-лист, картинки | **всё доступно** | всё доступно |
| Жизнь задачи, «в песочницу», удалить | нет | в меню `⋯` шапки; «Жизнь задачи» — свёрнутой строкой внизу |
| Что пишет | ничего до «Добавить»; затем **один** `POST` со всеми полями + загрузки картинок | дискретные контролы — сразу (как сейчас); текст и то, что распознано в тексте, — по «Сохранить» |
| Кнопка внизу | «Добавить» (+ долгий тап/второй вариант «Добавить и ещё») | «Сохранить», видна только при несохранённой правке |

Высоты:

- **compact** (быстрое добавление) — нижний лист над списком проекта по
  «+ Задача»: поле заголовка (минимум 2 строки, не однострочник — правило
  F12 сохраняется), строка атрибутов (п. 3), «Добавить». Потянуть вверх или
  тап `⤢` — тот же виджет на весь экран (`DraggableScrollableSheet` до 1.0),
  состояние не теряется. «Добавить и ещё» очищает поле и оставляет лист
  открытым — замена старого «пять фраз, пять Enter».
- **full** — открытие существующей задачи, открытие из диктовки, раскрытый
  compact. На ширине ≥ 720 (desktop/планшет, `adaptive_layout.dart`) — диалог
  560 px шириной вместо листа.

`UnsavedChangesGuard` — как сейчас: новая — грязная, если есть хоть что-то;
существующая — если текст/распознанное отличается от строки.

### Раскладка full (сверху вниз)

```
[×]  Новая задача                    [● Дом ▾]   [⋯]
┌────────────────────────────────────────────────┐
│ Купить корм коту ⟦завтра в 10⟧ #Дом            │  заголовок 22/600, растёт
│                                   [✨] [🎤]     │  Причесать, микрофон
└────────────────────────────────────────────────┘
 [⏰ Завтра, 10:00 ×] [📍 + Место] [☑ + Список] [🖼 + Фото] [▦ Категория]   ← строка атрибутов, скролл вбок
 ОПИСАНИЕ
 текст 17, ссылки подчёркнуты; под ним карточки ссылок
 СПИСОК · 2/5
 ☑ молоко   ☐ хлеб   ☐ + пункт
 КАРТИНКИ
 [▣][▣][+]

 [мини-карта 120 px · «Пятёрочка у дома» · 200 м]
 [ Открыта | Блокер | Сделано ]
 [ Взять в работу ]                       (существующая)
 Жизнь задачи · создана 3 д назад …       (существующая)
═══════════════════════════════════════════════════
 [              Добавить / Сохранить              ]  76 px, белая на тёмном
```

Секции ОПИСАНИЕ/СПИСОК/КАРТИНКИ/МЕСТО **не рисуются пустыми**: появляются,
когда в строке атрибутов нажали «+», и исчезают, когда опустели (описание —
исключение: у новой задачи оно открыто сразу, как сейчас). Так compact и
пустая задача короткие, а насыщенная — вся на виду.

Клавиатура поднята → прячутся нижние секции под сгибом, кнопка остаётся
прибитой (как `_saveBar` сейчас), строка атрибутов прилипает над клавиатурой
(как панель Todoist).

## 2. Распознавание прямо в тексте (по мотивам Todoist)

### Как это в Todoist (ориентир, не копия)

Quick Add разбирает строку на лету: «tomorrow 10am», «every monday»,
`#Проект`, `/Раздел`, `@метка`, `p1`–`p4`. Распознанный кусок подсвечивается
цветом прямо в поле; под полем — чипы с тем, что будет присвоено. На
сохранении кусок вырезается из названия (настраивается). Ложное срабатывание
снимается: тап/Backspace по подсветке — и кусок становится обычным текстом.

### Что берём (только то, что в TaskRadar уже есть)

| Токен | Куда | Пример |
|---|---|---|
| дата / время / относительное | `remindAt` + `remindTime` | «завтра в 10», «в пятницу в 18», «через 2 часа», «15 ноября» |
| `#проект` | проект (только у новой задачи) | `#дом`, `#Работа` |
| `/категория` | `categoryId` в выбранном проекте | `/покупки` |

**Не берём:** повторы («каждый понедельник») — повторяющихся напоминаний в
модели нет (`remindAt` — одна дата), фраза остаётся текстом; метки `@` и
приоритеты `p1` — их нет в продукте. Статус токеном не задаётся — для него
сегмент.

### Правила разбора дат (русский)

Чистая функция без часов и зоны внутри:
`List<SmartToken> parseSmartTokens(String text, {required DateTime now, required SmartContext ctx})`
в `app/lib/domain/smart_tokens.dart`. Регистр не важен, `ё` = `е`, только
целые слова, ничего внутри URL.

1. **День**: `сегодня`, `завтра`, `послезавтра`.
2. **День недели**: `(в|во)? (следующ(ий|ую|ее))? понедельник|пн|вторник|вт|
   среду|среда|ср|четверг|чт|пятницу|пятница|пт|субботу|сб|воскресенье|вс`.
   Ближайший такой день, сегодня включительно, если время ещё не прошло (или
   времени нет); «следующий» — тот, что на следующей неделе. Сокращения
   `пн…вс` — только с предлогом `в/во` или рядом со временем (иначе «вс»
   в тексте ловилось бы зря).
3. **Дата**: `15 ноября`, `15 ноя`, `15.11`, `15.11.2026`, `15/11`; `к 15
   ноября`, `до пятницы`, `к пятнице` — то же самое (дата напоминания).
   Без года и уже прошла в этом году → следующий год.
4. **Время**: `в 10`, `в 10:30`, `в 10.30`, `к 10`, `в 9 утра`, `в 12 дня`,
   `в 6 вечера` (→18:00), `в 2 ночи`, `в полдень` (12:00), `в 10 ч`,
   `в 10 часов`. Часы 1–7 без «утра/ночи» → +12 (в задачах «в 5» почти всегда
   17:00); 8–23 — как сказано. **Защита от ложных срабатываний:** `в N`
   считается временем, только если N ≤ 23 и за ним конец текста, знак
   препинания, `:мм`/`.мм`, «утра/дня/вечера/ночи/ч/час…», или рядом стоит
   дата/день. «в 2 этапа», «в 3 экземплярах» — не время.
5. **Только время** без дня → сегодня, если оно ещё впереди, иначе завтра.
6. **Относительное**: `через N минут|мин|часов|часа|ч|дней|дня|недель|недели|
   месяцев|месяца`, `через час|полчаса|неделю|месяц`, числа цифрами и словами
   `один…десять`, `пару` = 2. Минуты/часы → дата **и** время (локальные
   стенные часы, через полночь корректно); дни/недели/месяцы → только дата.
7. **Сочетания** в любом порядке, если между частями только пробелы:
   «завтра в 10», «в 18 в пятницу», «15 ноября в 9:30» — один токен.
8. Распознаётся **первое** выражение даты в тексте; следующие — обычный текст
   (без подсветки), чтобы «перенести с пятницы на понедельник» не путало.
9. Результат: `remindAt` = `calendarDateForApi(day)` (не трогать формат —
   ловушка из `domain/reminders.dart`), `remindTime` = `HH:MM` или null
   (тогда сработает в час из настроек). Уже прошедший момент («сегодня в 9»
   в 15:00) допустим — чип окрашен `alarm` с подписью «уже прошло».

`#проект` — префиксное совпадение по именам проектов пользователя (без учёта
регистра, пробелы в имени — через кавычки `#"Дача 2"` или по совпадению
первых слов); один кандидат — токен активен, несколько — всплывающий выбор под
курсором, ноль — не токен. `/категория` — так же по категориям выбранного
проекта; несуществующую **не создаём** из текста (только явной кнопкой в
листе категорий).

Тесты — таблица фраз → ожидаемый результат при фиксированном `now`
(в т. ч. полночь, 31 декабря, переход на летнее время не нужен — даты
календарные, но проверить «через 3 часа» в 23:00).

### Показ

- Поле заголовка (и описания) работает на `SmartTextController extends
  TextEditingController` с `buildTextSpan`: активный токен — заливка
  `voiceLevelHigh` 30 % + текст `voiceBright`, скругление; ссылка —
  подчёркивание; снятый токен — обычный текст.
- В строке атрибутов соответствующий чип заполняется и **вспыхивает** (короткий
  scale 1.0→1.08→1.0 и смена заливки, 180 мс) — это и есть «драйв»: напечатал
  «завтра в 10» — чип «⏰ Завтра, 10:00» ожил.
- **Тап по подсветке** → маленькое меню: «Не дата» (снять: кусок становится
  текстом, и этот же кусок в этой позиции больше не распознаётся — список
  снятых спанов в состоянии экрана) и «Изменить…» (пикер даты/времени).
  Backspace сразу после токена сначала снимает распознавание, вторым нажатием
  стирает символ (как в Todoist).
- **Сохранение**: распознанный кусок вырезается из заголовка, двойные пробелы
  и повисшие предлоги/запятые по краям подчищаются. Значение живёт в поле
  задачи (чип), а не в тексте. Переключатель в настройках не нужен.

### Источник правды

Состояние напоминания/проекта/категории — отдельное от текста. Токен
**пишет** в него, когда появляется или меняется; удалили текст токена —
значение возвращается к тому, что было до токена, если его с тех пор не
меняли руками. Ручная правка чипа после токена → токен снимается (подсветка
пропадает, текст остаётся).

У **существующей** задачи при открытии весь текст сканируется один раз и все
найденные куски помечаются снятыми: старое «позвонить в пятницу», сохранённое
до этой фичи, не должно молча переставить напоминание. Активны только куски,
набранные/надиктованные в этой сессии.

## 3. Строка атрибутов и контролы

Горизонтально прокручиваемый ряд чипов 36 px (мишень 44 — как `_FieldChip`),
под заголовком. Пустой чип — контур `voiceLine`, «+ Напомнить»; заданный —
заливка `voiceWell`, значение и `×`.

| Чип | Пустой | Заданный | Тап |
|---|---|---|---|
| ⏰ Напоминание | «+ Напомнить» | «Завтра, 10:00» / «Пт» / «15.11» (`formatReminderDate`) | лист: быстрые «Сегодня вечером / Завтра утром / В выходные / Через неделю» + календарь + `reminder_time_picker.dart` |
| 📍 Место | «+ Место» (скрыт, если в настройках выключено и задач с местом нет) | «Пятёрочка · 200 м» | экран выбора места (п. 7) |
| ☑ Список | «+ Список» | «2/5» | открывает/фокусирует секцию, новый пункт |
| 🖼 Картинки | «+ Фото» | «3» | меню: Галерея / Вставить из буфера / (скриншот-последний — если доступно) |
| ▦ Категория | «Без категории» | имя | `category_sheets.dart` как сейчас |

Чип проекта — в шапке (для новой). Статус — сегментом ниже (это не «атрибут
на потом», а состояние). Правило совместимости: напоминание **не меняет
статус** (как `board_reminders.dart`: напоминание есть у любой несделанной).
Надпись «задача будет ждать» в разборе диктовки этому противоречит — убрать
её в рамках WP4.

## 4. Диктовка и «Причесать» в редакторе

- Микрофон в карточке заголовка (как сейчас) → `DictationScreen` с
  `FieldDestination`. Для **новой** задачи `kind = ParseKind.task` (ответ несёт
  напоминание), для существующей — `taskTidy`, как сейчас. `FieldDictation`
  (`FieldTaskText`) получает необязательные `remindAt/remindTime`; вернувшееся
  напоминание кладётся в чип с пометкой AI (`AiSourceMark`), а не в текст.
- Вернувшийся текст считается «новым» → локальный разбор токенов идёт по нему,
  как по набранному. Если AI уже дал напоминание, токен-дата в том же тексте
  совпадает с ним и только подсвечивается.
- «Причесать» (`AiTidyScreen`, `taskTidy`) — как сейчас; промпт дат не
  добавляет. После замены текста уже применённые значения чипов остаются
  (источник правды — состояние, п. 2); вырезанный при причёсывании токен
  значение **не** откатывает (откат только при ручном стирании).
- Сквозной путь из микрофона проекта: экран разбора получает вторую кнопку
  **«Дополнить…»** рядом с «Добавить» — открывает `TaskEditor` (full, новая)
  с `prefill` (заголовок, описание, напоминание, `dictationParseId`). «Добавить»
  остаётся одним тапом — быстрый путь не удлиняем. Песочница не меняется.

## 5. Ссылки

- Поиск URL: `https?://…` и `www.…` в заголовке, описании, пунктах списка
  (одна функция `findLinks` в `domain/smart_tokens.dart`; даты внутри URL не
  ищутся).
- В поле — подчёркнуты; когда поле не в фокусе — тап открывает браузер
  (`url_launcher`, `LaunchMode.externalApplication`), долгий тап —
  «Копировать».
- Под описанием — карточки ссылок: иконка 🔗, заголовок страницы (если есть
  превью) или домен, домен мелко. Заголовок — с сервера
  (`GET /link-preview`, п. 8), кэш в памяти + в `read_cache_store`; офлайн —
  просто домен. В задаче ничего про ссылки не хранится.
- В строке списка задач — значок 🔗, если в тексте есть ссылка.

## 6. Чек-лист и картинки в редакторе

**Чек-лист.** Пункт = чекбокс + многострочное поле (17) + ручка перетаскивания
(`ReorderableListView`). Enter в пункте → новый пункт ниже; Backspace в пустом
→ удалить и фокус вверх; вставка многострочного текста в пункт → по пункту на
строку (маркеры `- `, `* `, `• `, `1.` срезаются). Отмеченные пункты остаются
на месте, текст зачёркнут `muted`. Заголовок секции «СПИСОК · 2/5» +
`⋯`: «Убрать отмеченные», «Удалить список». У существующей задачи отметка
галочки пишется **сразу** (это действие, не правка текста); текст пунктов —
по «Сохранить». В строке списка задач — «☑ 2/5».

**Картинки.** Лента миниатюр 96×96 (`Radii.row`), последней — плитка «+».
Источники: галерея (`image_picker`, мультивыбор), вставка из буфера
(`TextField.contentInsertionConfiguration` — картинка из клавиатуры Gboard; на
Windows/web — Ctrl+V через пакет буфера), «Поделиться» из другого приложения
(share intent: лист «Добавить в задачу…» → выбор: новая задача / последняя
открытая; новая открывается в редакторе с картинкой). Сжатие на телефоне до
отправки: длинная сторона ≤ 3000 px, PNG оставлять PNG, если ≤ 4 МБ (скриншот
с текстом не мылить), иначе WebP q85; фото → JPEG q85, без EXIF. Статус на
миниатюре: кольцо прогресса / часы (в outbox) / красная точка (отказ, тап —
«Повторить/Убрать»). Тап → полноэкранный просмотр с зумом, листанием,
«Удалить», «Поделиться». В строке списка — «🖼 3».

## 7. Напоминание по месту

- **Настройки**: группа «Напоминания» получает переключатель «По месту»
  (выключен по умолчанию). Включение: объяснение → точная геопозиция →
  «Разрешить всегда» (на Android 11+ — через системные настройки, кнопкой).
  Нет фонового доступа — чип места показывает «не сработает: нет доступа в
  фоне», тап ведёт в настройки.
- **Выбор места** (`screens/location_picker_screen.dart`): карта OSM
  (`flutter_map`, тайлы `tile.openstreetmap.org`, свой `userAgentPackageName`,
  атрибуция «© OpenStreetMap» обязательна), булавка по центру — двигаешь
  карту; «Моё место» (`geolocator`); радиус — ползунок 100–1000 м шаг 50,

  подпись — поле, по умолчанию «Место» (обратное геокодирование не делаем в
  v1). Поиск по адресу — нет (не просили).
- **Срабатывание**: только «при входе в зону». Уведомление через существующий
  шлюз (`lib/notifications/`): «Рядом: <подпись> — <задача>», тап открывает
  редактор. Повтор не чаще раза в 6 ч на задачу (локальная отметка). Сделанные
  задачи не регистрируются.
- **Регистрация**: чистая функция `geofencesFromBoard(board)` (аналог
  `remindersFromBoard`) → список `(taskId, lat, lng, radius)`; синхронизация
  с ОС при тех же событиях, что и `ReminderBridgeScope` (загрузка доски,
  правка, загрузка ОС — `RECEIVE_BOOT_COMPLETED` уже есть). Лимит Android —
  100 зон на приложение: берём 90 самых недавно изменённых, остальным чип
  «не отслеживается (лимит)». Windows/web — выбор и показ работают, зон нет:
  чип «только на телефоне».
- Место и дата независимы: у задачи может быть и то, и другое.

## 10. Данные и API

### Task: новые поля

```prisma
model Task {
  // ...
  /// Чек-лист: [{ id, text, done }] или null. JSON, а не таблица: пункты
  /// никто не запрашивает отдельно, а целиком список проходит через
  /// существующий PATCH + `expected` (конфликт офлайн-очереди — на весь
  /// список, для личного трекера достаточно).
  checklist Json?

  /// Напоминание по месту: все четыре или ни одного (CHECK в миграции).
  locLat    Float?
  locLng    Float?
  locRadius Int?     // метры, 100..1000
  locLabel  String?  // ≤ 80

  attachments TaskAttachment[]
}

model TaskAttachment {
  id         String   @id @default(cuid())
  taskId     String
  task       Task     @relation(fields: [taskId], references: [id], onDelete: Cascade)
  /// Идемпотентность загрузки из outbox, как `createKey`.
  uploadKey  String
  mime       String   // image/png | image/jpeg | image/webp
  sizeBytes  Int
  width      Int
  height     Int
  sha256     String
  createdAt  DateTime @default(now())
  @@unique([taskId, uploadKey])
  @@index([taskId, createdAt])
  @@map("task_attachments")
}

model LinkPreview {
  url       String   @id
  title     String?
  siteName  String?
  failed    Boolean  @default(false)
  fetchedAt DateTime @default(now())
  @@map("link_previews")
}
```

Пункт чек-листа: `id` — генерирует клиент (8–40 символов), `text` 1–500,
`done` bool; до 200 пунктов; `[]` сохраняется как `null`.

### Схемы (`backend/src/schemas.ts`)

- `createTaskSchema` и `updateTaskSchema` получают
  `checklist: ChecklistItem[] | null` и
  `location: { lat: -90..90, lng: -180..180, radius: 100..1000 int, label?: string ≤80 } | null`
  (в базе — четыре колонки; наружу — объект `location` или null).
- `expected` получает `checklist` и `location`; `sameValue` в
  `routes/tasks.ts` сравнивает их глубоко (порядок пунктов значим).
- Ответ задачи (везде: `GET /projects/:id/tasks`, `/board`, `PATCH`, `POST`)
  несёт `checklist`, `location`, `attachments: [{ id, mime, width, height, sizeBytes, createdAt }]`.
  Файлы в доску не едут — только метаданные.

### Вложения: хранение и маршруты

- Диск: том `attachments-data` в `compose.prod.yaml` (и `compose.ci.yaml`),
  смонтирован в бэкенд как `/var/lib/taskradar/attachments`, путь —
  `ATTACHMENTS_DIR`. Файл: `<userId>/<attachmentId>.<ext>`, миниатюра
  `<userId>/<attachmentId>.thumb.webp`. Наружу файлы отдаёт только API (с
  проверкой владельца), Caddy их напрямую не видит.
- Миниатюра — на сервере, `sharp`, длинная сторона 512, WebP q75, при
  загрузке.
- Лимиты (env с умолчаниями): `ATTACHMENT_MAX_BYTES` = 10 МБ на файл,
  30 на задачу, `ATTACHMENT_USER_QUOTA_BYTES` = 2 ГБ на пользователя;
  тип по сигнатуре байтов (не по заголовку), только PNG/JPEG/WebP; JPEG
  перекодируется без метаданных (GPS из фото не хранить).
- Маршруты:
  - `POST /tasks/:id/attachments` — multipart (`@fastify/multipart`), поля
    `file`, `uploadKey`. 201 + вложение; повтор с тем же `uploadKey` → 200 и
    то же вложение. 413 — размер/квота, 415 — тип, 409 — 30 уже есть.
  - `GET /attachments/:id` и `GET /attachments/:id/thumb` — Bearer,
    `Cache-Control: private, max-age=31536000, immutable`, `ETag` = sha256.
  - `DELETE /attachments/:id` — 204; строка удаляется, файлы — после коммита,
    best effort.
  - Удаление задачи/проекта — каскад строк; файлы-сироты чистит
    `src/scripts/sweepAttachments.ts` (запуск из того же крона/таймера, что
    и бэкап, раз в сутки).
- `POST /tasks/:id/unfile` (в песочницу): чек-лист дописывается в текст
  строки песочницы пунктами `- …`, место теряется, картинки удаляются —
  клиент спрашивает подтверждение, если они есть.
- Бэкапы: `BACKUPS.md` и скрипт бэкапа на сервере — архив тома вложений рядом с
  дампом БД; `scripts/pull-production-backup.ps1` тянет и его. (У владельца
  этот скрипт сейчас изменён локально — WP1 сначала спрашивает, а не
  перезаписывает.)
- Caddy: проверить, что лимит тела запроса не меньше 12 МБ на хост
  TaskRadar (общий Caddy — правки только по `DEPLOYMENT.md`).

### Превью ссылок

`GET /link-preview?url=…` → `{ url, title, siteName }` или 204. Сервер:
только http/https, DNS-резолв и отказ для приватных/loopback/link-local
адресов (SSRF), таймаут 5 с, читать ≤ 512 КБ, `og:title` → `<title>`; кэш в
`link_previews` 30 дней (неудачи — сутки). Лимит запросов — как у AI, но
отдельный счётчик (100/сутки).

### Офлайн-очередь (`app/lib/storage/outbox_store.dart`)

- Чек-лист, место, напоминание, статус, категория новой задачи — **в теле
  того же `createTask`**: ничего нового.
- Правки существующей — тот же `editTask` с `expected` (теперь и для
  `checklist`, `location`). Галочка пункта офлайн = `editTask` со всем
  списком; конфликт → обычный экран «пропущено» из `outbox_history.dart`.
- Новые виды `OutboxKind`:
  - `uploadAttachment` — `body: { uploadKey, mime, localPath }`; `taskId`
    — id задачи **или** `local:outbox:<createKey>` (картинка к ещё не
    отправленной задаче). Файл копируется в
    `<support>/outbox_files/<key>.<ext>` в момент постановки и удаляется
    после `sent`. При отправке: если задача — локальная, ждать, пока
    `createTask` с этим ключом станет `sent`, и взять его `taskId` (очередь
    шлёт по порядку, так что create всегда раньше). Повтор безопасен за счёт
    `uploadKey`.
  - `deleteAttachment` — `taskId`, `body: { attachmentId }`; 404 = `sent`.
- `outbox_overlay.dart` рисует ожидающие картинки из `localPath` в ленте и
  счётчике строки, как сейчас рисует ожидающие создания.
- Версию формата файла outbox поднять; старые записи читаются как есть.
