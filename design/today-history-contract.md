# TaskRadar — «Сегодня», История, пересмотр, ритм: контракт для реализации

Принят 27.11.2026 по итогам двух сессий обсуждения с владельцем. Решения и их
смысл — `today-decisions.md` и `history-review-decisions.md`, прочитайте оба
**до** этого файла. Этот файл — общий для агентов бэкенда, дизайна и приложения:
данные и API здесь **обязательны**; внешний вид — в `today-history-spec.md` и
`reference/` (делает дизайн-агент). Если что-то здесь оказывается невозможным
или противоречивым — меняйте контракт **в этом файле** и пишите, что и почему,
в отчёте.

Чего **не** делаем: новых статусов задач, дедлайнов, размеров задач,
отдельного «плана недели» или «списка дня» как сущности.

## Слова

- **Дата задачи** — существующие `Task.remindAt` (дата) + `remindTime`
  ("HH:MM" | null). В БД и API **не переименовываются** (как заметки → идеи).
  Новый смысл: «когда этим заняться». В интерфейсе — «дата», не «напоминание».
- **Сегодня** — незакрытые (pending/blocked) задачи с датой = сегодня, плюс
  закрытые сегодня задачи с датой ≤ сегодня (зачёркнутые, внизу).
- **С прошлых дней** (хвост) — незакрытые задачи с датой < сегодня.
- **Позже** — незакрытые задачи с датой > сегодня + горизонт (дней).
- **Сегодня** везде — локальный день владельца. Клиент шлёт
  `tzOffsetMinutes` (как `/history` сейчас); MCP и всё, что без клиента,
  считают по UTC.

## Данные

### Задача: что меняется

| поле | тип | смысл |
|---|---|---|
| doneAt | DateTime? | когда закрыта. Ставится при переходе в done, снимается при выходе из done. Бэкфилл миграцией: `at` последнего события `status→done` (иначе `updatedAt`) у задач со статусом done |

Позиция при закрытии не меняется (так и сейчас), поэтому «вернуть на своё
место» — это просто сменить статус.

### Журнал (`TaskEvent`)

- Новое поле `contourId String?` — у событий `focused`/`unfocused` пишется
  контур рабочего набора (для «Вернуть» и истории). Старые строки — null.
- Новое поле `revokedAt DateTime?` — у события `status→done`, закрытие которого
  отменено. Отменённое закрытие **не считается** нигде (Сделано, счётчики,
  путемер, ритм, пересмотр).
- Новый `kind` `reopened` (fromStatus done → toStatus прежний). Пишется
  `POST /tasks/:id/reopen`. Журнал в редакторе показывает его как «возвращена».
- Правило: **любой** выход из done (reopen или обычный PATCH статуса) ставит
  `revokedAt` последнему неотменённому `status→done` этой задачи. Закрыл и
  передумал — это не закрытие.

### Настройки владельца (на сервере, общие для всех устройств)

Поля `User`:

| поле | тип | по умолчанию | смысл |
|---|---|---|---|
| laterHorizonDays | int 1..90 | 10 | горизонт «Позже» |
| reviewWeekday | int 1..7 (1 = пн) | 1 | день пересмотра |
| reviewTime | "HH:MM" | "09:00" | время пересмотра |

Клиентская настройка «час напоминаний без времени» **удаляется** (в UI и в
планировщике): задачи без времени больше не пушат.

### Ритм проекта

Поля `Project`: `rhythmClosedPerWeek Int?` (1..50), `rhythmMaxOpen Int?`
(1..500). Оба необязательны, ритм включён, если задано хоть одно.

Вычисляемое (сервер, в ответах проекта) `rhythm`:

```
rhythm: null | {
  closedPerWeek: number | null,   // норма (как задано)
  maxOpen: number | null,         // потолок
  closedAvg: number,              // закрыто за последние 14 дней / 2, неотменённые
  open: number,                   // pending + blocked
  lastClosedAt: string | null,
  silentWeeks: number,            // полных недель с lastClosedAt (или с createdAt проекта)
  signal: "silence" | "overflow" | null  // silence: closedAvg < closedPerWeek; overflow: open > maxOpen; оба → overflow
}
```

## Вычисления (чистые функции в `backend/src/domain/`, с тестами)

- `isLater(task, today, horizonDays)` — незакрытая и `remindAt > today + horizon`.
- **current** (`isCurrent`) — первая pending задача проекта, **которая не
  «Позже»**. Горизонт — владельца; «сегодня» сервера — UTC (ошибка на сутки
  у границы горизонта допустима).
- **nextStep цели** — первая pending задача цели, не «Позже»; если все pending
  «Позже» — первая pending.
- `todayView(tasks, today)` → `{ date, today: [...], doneToday: [...], tail: [...] }`:
  - `today` — незакрытые с датой = today; порядок: сначала со временем (по
    времени), затем без времени по скоупу → проекту → позиции;
  - `doneToday` — done, `doneAt` в локальном дне today, дата ≤ today; по `doneAt`;
  - `tail` — незакрытые с датой < today; по дате, затем позиции.
- `reviewDue(user, lastReview, now, tz)` → `{ due, nextAt, lastAt }`. Пересмотр
  «пора», если наступил ближайший момент `reviewWeekday`/`reviewTime` после
  `lastAt` (или пересмотров ещё не было и наступил первый такой момент после
  регистрации/миграции).

## API (всё под авторизацией, только своё)

Существующие ответы задач (`taskView`, `/board`, `/focus`, `/tasks/:id`) —
добавляют `doneAt`. Ответы проектов (`/board`, `/projects`) — добавляют
`rhythmClosedPerWeek`, `rhythmMaxOpen`, `rhythm`.

| метод | путь | что |
|---|---|---|
| GET | `/settings` | `{laterHorizonDays, reviewWeekday, reviewTime}` |
| PATCH | `/settings` | любое подмножество этих полей; 400 на неверное |
| GET | `/today?tzOffsetMinutes=` | `todayView` с полными задачами (как `taskView` + `projectName`, `scopeId`, `scopeName`) |
| POST | `/tasks/:id/reopen` | только из done. Статус ← `fromStatus` последнего неотменённого `status→done` (pending, если нет). Если в той же транзакции закрытия было `unfocused` с `contourId` (или с null — контур по умолчанию) — вернуть в рабочий набор этого контура (`focused` с `contourId`). `revokedAt` у закрытия, событие `reopened`, `doneAt = null`. 409 `not_done` если задача не done. Ответ — `taskView` |
| GET | `/history/done?before=&limit=&tzOffsetMinutes=` | неотменённые закрытия, свежие сверху: `{items: [{task: taskView + projectName, doneAt}], nextBefore}`; `limit` 1..100, по умолчанию 50; `before` — ISO `doneAt` для пагинации. Повторно закрытая задача — одна строка (по текущему `doneAt`) |
| GET | `/history/weeks?weeks=&tzOffsetMinutes=` | `{weeks: [{start: "YYYY-MM-DD" (пн), closed, byProject: [{projectId, name, closed}], review: Review \| null}]}`, свежие сверху, `weeks` 1..52, по умолчанию 12 |
| GET | `/reviews/status?tzOffsetMinutes=` | `reviewDue` |
| GET | `/reviews/draft?tzOffsetMinutes=` | данные для шагов, см. ниже |
| POST | `/reviews` | `{summary?, tzOffsetMinutes}` — сервер сам считает период и числа и сохраняет запись; ответ — Review |
| GET | `/reviews?limit=` | записи, свежие сверху |
| PATCH | `/projects/:id` | + `rhythmClosedPerWeek`, `rhythmMaxOpen` (null — выключить) |

`GET /history` (старый) **оставить** для старых версий приложения; новое
приложение его не зовёт.

`/reviews/draft` →

```
{
  periodStart, periodEnd(now), monthly,
  done:      [{task, doneAt}] по проектам (группировку делает клиент),
  intended:  [{task, reasons: ["workingSet" | "goalStep" | "dated"]}]  // незакрытые: в рабочем наборе любого контура, nextStep цели в слоте, дата в периоде
  goals:     GoalView[] в слотах всех контуров (с windowEndsAt / windowExpired) + bench,
  rhythm:    [{project, rhythm}] где signal != null,
  month:     null | { byProject: [{projectId, name, closed}], achievedGoals: GoalView[] }  // если monthly: прошлый календарный месяц
}
```

Шаги пересмотра действуют **существующими** маршрутами (PATCH задачи, focus,
goals, projects). `POST /reviews` только записывает итог.

«Следом…» — клиент создаёт задачу обычным `POST /projects/:id/tasks` с датой.
«Все в сегодня» и разбор хвоста — обычные PATCH по задачам (офлайн-очередь
работает как есть).

## Правила интерфейса (поведение; вид — в спецификации дизайна)

### «Работа»

- Сверху вниз: блок целей → **«С прошлых дней»** (если не пуст) → **«Сегодня»**
  → рабочий набор (как сейчас). «Сегодня» рабочий набор не занимает, пул не
  скрывает, дуэли нет.
- «Сегодня»: компактные строки с галочкой; подзаголовки по скоупам; сверху
  счётчик «N из M» (M = today + doneToday, N = doneToday); у задачи со временем —
  время; корона, если задача в цели; закрытые — зачёркнуты внизу до конца дня.
  Тап по строке — редактор задачи.
- Заблокированная в «Сегодня» — с замком и «проверить»; действия
  «Разблокировать» (status pending, дата остаётся) и «Ещё ждём» (выбор даты).
- «С прошлых дней»: у строки — сколько дней назад; действия «Сегодня» /
  «Дата…» / «В стопку» (снять дату); общая кнопка «Все в сегодня». Не блокирует
  ничего.
- Офлайн: «Сегодня» считается на клиенте из закешированных задач (той же
  логикой, что `todayView`, с тестами), сервер `/today` — для MCP и сверки.

### Стопка и проекты

- У задачи в списках (проект, пул) — быстрые действия «Сегодня» / «Завтра»
  (там, где сейчас действия строки; точное место — спецификация).
- Метка даты у строки: «сегодня», «завтра», «чт 28.11», «3 дн. назад» —
  вместо нынешнего «пора · DD.MM».
- Задачи «Позже» (включая заблокированные) сворачиваются в одну строку внизу
  проекта: «Позже: N · ближайшая 25 фев»; тап — раскрыть.
- План: у проекта с `rhythm.signal` — приглушённая метка «тишина N нед» /
  «перебор 24/20». Без красного, без пушей.
- Ритм настраивается в меню проекта (`_ProjectMenu`): пункт «Ритм…» — лист с
  двумя необязательными числами.

### Уведомления

- Пушат **только** задачи со временем (`remindTime`). Задачи с одной датой —
  нет; утреннего пуша нет.
- Пересмотр: один локальный пуш в `reviewWeekday`/`reviewTime`, если
  пересмотр не пройден. Пропущен — метка на вкладке «История», без повторов.

### Редактор задачи

- Чип «Дата» вместо «Напоминание»: быстрые «Сегодня», «Завтра», «Пн», выбор
  дня; время — отдельным необязательным шагом с подписью «пуш в это время».

### «Следом…»

- После отметки «сделано» (в «Работе», «Сегодня», проекте) — на несколько
  секунд снекбар/кнопка «Следом…» рядом с «Отменить». Открывает короткий лист:
  заголовок (пустой, с подсказкой «что дальше по: <задача>»), быстрые даты
  «через 3 дня / неделю / 2 недели / дата…»; создаёт задачу в том же проекте.
- Та же кнопка — у строки в «Сделано» и на шаге 1 пересмотра.

### «История»

- Две вкладки: **«Сделано»** (по умолчанию) и **«Недели»**. Переключатель
  «Офлайн» (outbox) остаётся, как есть.
- «Сделано»: группы «Сегодня» / «Вчера» / «пн 24.11», строка — заголовок,
  проект, время закрытия; действия «Вернуть» и «Следом…»; подгрузка при
  прокрутке. Сверху — карточка пересмотра, **только** если `due`.
- «Недели»: недельные столбики закрытого (12 недель), под каждой неделей —
  запись пересмотра (итог, числа) если есть; достигнутые цели (как сейчас
  `_AchievedGoalsSection`). Старые «Висит дольше всего» и дневной график —
  убрать.
- Пересмотр — полноэкранный поток из 6 шагов (каждый «Пропустить»), данные из
  `/reviews/draft`, в конце `POST /reviews`. Разделы по контурам там, где это
  имеет смысл (цели, рабочие наборы).

### Настройки

- «Горизонт «Позже»» (дни), «Пересмотр» (день недели + время) — на сервере.
- Убрать «Напоминания без времени приходят в …».

### Виджет (Android)

- Строка-сводка «Сегодня 3 из 7» и ближайшая сегодняшняя задача со временем
  («15:00 Встретить курьера»); тап — «Работа». Над строками рабочего набора,
  под строками целей. Поставить заново виджет не должно требоваться.

## Миграция

- Колонки и таблица выше; бэкфилл `doneAt`.
- Даты задач не трогать: прошедшие окажутся в «С прошлых дней» (решение
  владельца), время у будущих сохраняется.
- Caddy: новые пути `/settings`, `/today`, `/reviews*`, `/history/*` должны
  проксироваться на бэкенд — проверьте списки путей в обоих Caddyfile в
  `deploy/` и раздел в `DEPLOYMENT.md` (прод-Caddy правит координатор).

## Уточнения по реализации бэкенда (27.11.2026)

Дополнения и уточнения, которых в контракте не было. Сказанное выше не
отменяется, кроме явно отмеченного.

### Данные и подсчёт

- **Все счётчики закрытий берутся из `Task.doneAt`**, а не из журнала:
  «Сделано», «Недели», ритм, `POST /reviews`, разделы черновика. Это то же
  самое, что «неотменённые закрытия»: любой выход из done отменяет закрытие и
  чистит `doneAt`, поэтому у задачи не больше одного действующего закрытия, и
  оно — её `doneAt`. Так список «Сделано» и числа не могут разойтись. Задача,
  созданная сразу done (`POST /projects/:id/tasks` со `status: "done"`),
  получает `doneAt` и считается. Старый `GET /history` по-прежнему считает по
  журналу — с `revokedAt: null`.
- **Миграция отменяет и старые закрытия**: каждое `status → done`, после
  которого журнал уже выводил задачу из done обычной сменой статуса, получает
  `revokedAt` = момент этого выхода. Правило «закрыл и передумал» действует и
  на историю до релиза.
- `TaskEvent.contourId` — внешний ключ на `contours` с `ON DELETE SET NULL`:
  удалённый контур превращает «Вернуть» в возврат в контур по умолчанию.
- События одной смены (закрытие и выход из набора, `reopened` и `focused`)
  пишутся с **одним `at`**. «Вернуть» ищет выход из набора, относящийся к
  закрытию, как `unfocused` в пределах ±2 с от закрытия (старые строки
  писались с разницей в миллисекунды).
- `GoalView.tasks[]` получили `remindAt`. Следующий шаг цели во всех ответах
  (`/goals`, `/goals/:id`, действия, MCP) считается с горизонтом владельца.
- `current` (`isCurrent`) учитывает «Позже» в `/board`,
  `GET /projects/:id/tasks` и MCP `list_tasks`. Если все pending — «Позже»,
  текущей нет.
- Ошибка «Вернуть» не из done: 409 `{ error: "not_done", message }`.

### Маршруты

- `/settings`: `PATCH` с неизвестным ключом — 400 (схема строгая); пустое тело
  возвращает текущие настройки.
- `/today`: задачи архивных проектов не входят (как на доске). Задача — это
  `taskView` + `projectName`, `scopeId`, `scopeName` (без `isCurrent`).
  «Порядок по скоупу → проекту → позиции» = `scope.position`, затем
  `project.createdAt` (порядок доски), затем `position`.
- `POST /tasks/:id/reopen`: если задача почему-то уже в наборе — в набор не
  возвращается повторно. Без закрытия в журнале — `pending`, без набора.
  Ответ — `taskView`.
- `/history/done`: `task` — тот же расширенный вид, что в `/today` (есть
  `scopeId`, `scopeName`). Задачи архивных проектов входят: сделанное
  сделано. Порядок `doneAt` по убыванию, затем `id`; `before` — строго
  раньше (две задачи, закрытые в одну миллисекунду на границе страницы, —
  принятый риск). `tzOffsetMinutes` принимается, но не нужен: дни
  группирует клиент.
- `/history/weeks`: неделя — от локального понедельника 00:00 до следующего.
  `review` недели — последний пересмотр, чей `periodEnd` попал в неделю.
  `byProject` везде — по убыванию `closed`, затем по имени.
- `/reviews/status`: пока пересмотров не было, отсчёт идёт от
  `max(user.createdAt, 2026-11-27T00:00Z)` (дата введения пересмотров), чтобы
  у существующих пользователей пересмотр не стал «пора» сразу после релиза.
  `nextAt` — момент, когда пересмотр стал или станет «пора» (если `due`, он в
  прошлом).
- Первый пересмотр **не** месячный (не с чем сравнить месяц). Месячный раздел
  черновика: `month: { month: "YYYY-MM", byProject, achievedGoals }` — поле
  `month` добавлено; это календарный месяц перед месяцем `periodEnd`
  (локально).
- `/reviews/draft`:
  - `done` — по `doneAt` по возрастанию;
  - `intended`: «dated» — дата в локальных днях от `periodStart` до
    `periodEnd` включительно, только неархивные проекты; рабочий набор и шаг
    цели — без этого ограничения. Порядок: сначала рабочий набор (по
    `focusedAt`), затем по дате, затем по позиции;
  - `goals` — слоты и скамейка всех контуров, по контуру и позиции;
  - `rhythm[]` — `{ project, rhythm }`, где `project` — строка проекта как в
    `GET /projects` (с `rhythmClosedPerWeek`, `rhythmMaxOpen`), только
    неархивные проекты.
- `POST /reviews`: тело необязательно; `summary` обрезается, пустая строка —
  `null`. **Повтор идемпотентен**: если последний пересмотр пользователя
  записан меньше 10 минут назад, это повтор того же запроса (потерянный ответ,
  двойное нажатие) — ответ 200 с этой записью; переданный непустой `summary`
  заменяет итог, период и числа остаются от первого запроса. Новая запись —
  201.
- Ритм (`rhythm`) есть во всех ответах о проекте: `GET /projects`,
  `GET /projects/:id`, `POST /projects`, `PATCH`, `archive`/`unarchive`,
  `/board`. `closedAvg` бывает дробным (3 закрытия за 14 дней → 1.5).
  `lastClosedAt` — наибольший `doneAt` в проекте.

### MCP

- `list_today { tzOffsetMinutes? }` → `{ date, today, doneToday, tail }`,
  задачи в виде `list_tasks` + `project`, `scope` (имена).
- `list_done { limit? (50), before? (ISO) }` → `{ tasks, more? }`, у задач
  `doneAt`, `project`, `scope`.
- `list_reviews { limit? (20) }` → `{ reviews: [{ id, periodStart, periodEnd,
  closed, byProject, achievedGoals, monthly?, summary? }] }`.
- `list_projects`: `rhythm` только у проектов с ритмом.

## Решения координатора по вопросам дизайна (27.11.2026)

Ответы на раздел «Вопросы к контракту» в `today-history-spec.md` (§15).
Пункты 2 и 3 решил владелец.

1. **Порядок в «Сегодня»**: клиент группирует по скоупу, внутри скоупа —
   сначала задачи со временем (по времени), затем остальные.
2. **Повтор в «Работе»** (владелец): задача рабочего набора с датой
   «сегодня» показывается **только в «Сегодня»** (с точкой «в работе»), из
   списка набора её убрать. Шаг цели с датой «сегодня» остаётся и в блоке
   целей, и в «Сегодня».
3. **«Снять» на шаге 2 пересмотра** (владелец): «снять с недели» — убрать из
   рабочего набора и снять дату; задача остаётся в проекте. Не удаление и не
   закрытие.
4. Быстрые «Сегодня» / «Завтра» / «В стопку» **снимают время**; лист даты
   время сохраняет.
5. Закрытые сегодня задачи **без даты** в «N из M» не считаются. Так и задумано.
6. «Вернуть» без сети **недоступна** (кнопка выключена с подписью). В очередь
   офлайна reopen не добавляем.
7. Виджет при M = 0 и непустом хвосте показывает «С прошлых дней: N».
8. Подсказка о свайпе — один раз, как предлагает спецификация.
9. Пересмотр начинается только при сети. Прерванное «Записать» повторяется,
   когда сеть вернётся: `POST /reviews` идемпотентен (см. уточнения бэкенда).

## Уточнения по реализации приложения (27.11.2026)

Что приложение сделало иначе или додумало сверх контракта и спецификации.

- **Закрытие больше не снимает дату.** Раньше клиент при «сделано» слал
  `remindAt: null` (и в строке, и в действии уведомления). Тогда `doneToday`
  был бы всегда пуст, поэтому дата теперь остаётся; закрытая задача пушей не
  даёт (фильтр по статусу), «Вернуть» возвращает её в свой день.
- **«Сегодня» считает клиент** из доски с применённой офлайн-очередью
  (`domain/today_view.dart`, тесты повторяют случаи бэкенда). `GET /today`
  приложение не зовёт. Смена суток — без таймера: день пересчитывается при
  открытии «Работы» и при каждой перестройке блока; телефон, оставленный на
  «Работе» через полночь, покажет вчерашний день до первого касания.
- **«Без сети»** для подписей и выключенных кнопок («Вернуть», «Начать»
  пересмотр, настройки на сервере) = последнее обновление доски упало по сети
  (или значение пришло из локальной копии).
- **Цепочка «Блокер → дата»** из строки и редактора по-прежнему открывает
  стандартные выбор дня и времени, а не тёмный лист даты (поведение то же).
  Правка распознанной в тексте даты («Изменить…» на подсветке) тоже пока
  открывает старый лист напоминания.
- **Локальная память интерфейса** (`SettingsStore.readUiNote`): «Сегодня»
  свёрнуто до конца дня, «Позже» раскрыто — по проекту, подсказка о свайпе
  показана один раз. Место в незаконченном пересмотре помнится только до
  перезапуска приложения.
- **Тексты снекбаров**, которых не было в спецификации: «На завтра», «Дата
  снята», «2 задачи на сегодня».
- **Пересмотр, шаг 2:** «Снять» по ответу 3 = убрать из набора и снять дату —
  то же действие, что «В стопку», отличается только подписью («снята»).
  **Шаг 3:** продление окна через API не откатывается, поэтому «Вернуть» на
  плашке «Продлено» только убирает плашку.
- **Числа в карточке пересмотра** («закрыто N», «целей в окнах») оцениваются
  по загруженным страницам «Сделано» и списку целей; точные числа — в
  черновике (`/reviews/draft`) при начале пересмотра. В пуше пересмотра N —
  закрытые на доске с `doneAt` после прошлого пересмотра.
- **Виджет:** строка «Сегодня» считается при публикации снимка приложением;
  ближайшее время может устареть, пока приложение не запускалось.
