# TaskRadar — цели, идеи, контуры: контракт для реализации

Принят 24.11.2026 по итогам сессии обсуждения с владельцем. Общий документ для
агентов бэкенда, дизайна и приложения: данные и API здесь — **обязательны**;
внешний вид — в `goals-ideas-spec.md` и `reference/` (делает дизайн-агент).
Если по ходу работы что-то здесь оказывается невозможным — меняйте контракт
**в этом файле** и пишите, что и почему, в отчёте.

## Зачем

Задачи выбираются по удовольствию и свежести, а не по пользе: полезная, но
неприятная или неясная задача не попадается на глаза — человек помнит, куда
записал свежую мелочь, и идёт прямо к ней. Вторая боль: мысли выглядят
невыполненными задачами, и сигнал «лежит» обесценивается.

Ответ:

- **Цели** — небольшое число результатов, стоящих в **слотах** на **окно**
  (например, неделю). У цели есть «зачем» и **следующий шаг**; её задачи помечены
  **короной**. Цель перехватывает выбор: блок целей сверху экрана «Работа» и в
  виджете, а при взятии в работу задачи вне целей — **дуэль** со следующим шагом.
- **Контуры** — наборы слотов, например «Работа» и «Личное», которые действуют в
  разное время. Задаёт их пользователь; к скоупам и проектам они **не привязаны**.
- **Идеи** — бывшие заметки: то, что может стать задачей, без возраста и
  без статуса.

Чего **не** делаем: новых статусов задач (остаются pending/blocked/done), тегов и
«связывания задач», дерева целей, общего списка идей вне проектов.

## Сущности

### Контур (`Contour`, таблица `contours`)

| поле | тип | смысл |
|---|---|---|
| id | cuid | |
| userId | FK User, Cascade | |
| name | string 1..40 | «Работа», «Личное» |
| slots | int 1..5, по умолчанию 2 | сколько целей одновременно в слотах |
| windowDays | int 1..90, по умолчанию 7 | окно цели по умолчанию |
| schedule | Json? | `null` или `{ "days": [1..7], "from": "HH:MM", "to": "HH:MM" }` (1 = понедельник, локальное время владельца; `from < to`, через полночь не бывает) |
| position | float | порядок; первый — контур по умолчанию |
| createdAt / updatedAt | | |

У пользователя **всегда есть хотя бы один контур**. Миграция создаёт каждому
существующему пользователю контур «Основной» (slots 2, windowDays 7, без
расписания); регистрация нового пользователя — тоже. Удалить последний контур
нельзя (409); удалить контур, в котором есть цели (любые, включая достигнутые),
нельзя (409, как у скоупов) — сначала перенести цели.

**Ручной выбор активного контура** хранится на пользователе:
`User.activeContourId String?` (FK SetNull) и `User.activeContourUntil DateTime?`.

**Какой контур активен** — решает клиент (сервер не знает часового пояса
устройства в момент запроса), функция `resolveActiveContour(contours, override,
now)`:

1. если `activeContourId` задан и (`activeContourUntil` null или в будущем) —
   он;
2. иначе первый по `position` контур, чьё `schedule` покрывает `now`;
3. иначе первый по `position`.

При ручном переключении клиент ставит `until` = ближайший момент, когда пункт 2
дал бы другой результат (смена расписания), а если ни у одного контура нет
расписания — `null` (до следующего ручного переключения).

### Цель (`Goal`, таблица `goals`)

| поле | тип | смысл |
|---|---|---|
| id | cuid | |
| userId | FK User, Cascade | |
| contourId | FK Contour, Restrict | в чьих слотах живёт |
| title | string 1..200 | |
| why | string? ≤ 300 | «зачем» / «что будет, если отложить» — одна строка |
| slottedAt | DateTime? | когда поставлена в слот; `null` = не в слоте |
| windowDays | int? 1..90 | своё окно; `null` = окно контура |
| windowEndsAt | DateTime? | конец окна; задаётся при постановке в слот и продлении |
| achievedAt | DateTime? | достигнута (закрывается только вручную) |
| position | float | порядок внутри контура (слоты и скамейка — один порядок) |
| createdAt / updatedAt | | |

Состояние выводится, не хранится:

- `achieved` — `achievedAt != null`;
- `slot` — `slottedAt != null` (и не achieved);
- `bench` — иначе («скамейка»).

`windowExpired = state == slot && windowEndsAt <= now`. Истёкшее окно **ничего
не делает само**: цель остаётся в слоте, клиент показывает вопрос «оставить /
на скамейку / достигнута».

### Связи

- `GoalTask` (`goal_tasks`): `goalId` (Cascade), `taskId` (Cascade), `position`
  float, `createdAt`; первичный ключ `(goalId, taskId)`. Задача может быть в
  нескольких целях, в том числе разных контуров, и из любых проектов владельца.
- `GoalIdea` (`goal_ideas`): `goalId` (Cascade), `noteId` (Cascade), `createdAt`;
  ключ `(goalId, noteId)`.

**Следующий шаг цели** = первая по `GoalTask.position` связанная задача со
статусом `pending`. Если такой нет — `null`, и клиент показывает шаг
«Обсудить» (если при этом есть blocked-задачи — подпись «всё заблокировано»).

### Задача: что меняется

- `Task.focusContourId String?` (FK Contour, SetNull) — в рабочий набор какого
  контура задача взята. Миграция: всем задачам с `focusedAt != null` — контур
  «Основной» их владельца. **У каждого контура свой рабочий набор.**
- В представлении задачи (`taskView`, везде, где задача отдаётся: доска,
  проект, focus, `GET /tasks/:id`, MCP) появляются
  `focusContourId` и `goals: [{ id, title, contourId }]` — только цели, которые
  **не** достигнуты. Это источник **короны**.

### Идея = заметка

Модель, таблица и маршруты `/notes` **не переименовываются** (меньше
миграций и риска); в интерфейсе, MCP-описаниях и `SKILL.md` — «идеи». Идеи
живут только в проектах; для идей без проекта владелец заводит проект-копилку
сам (кода не нужно).

Новое: `POST /notes/:id/to-task` — в одной транзакции создаёт задачу в конце
того же проекта (`title` = заголовок идеи, `description` = текст идеи или
null), переносит связи `GoalIdea` этой идеи в `GoalTask` (в конец цели),
удаляет идею, пишет событие `created` в журнал задачи. Ответ — задача
(`taskView`).

## API (всё под авторизацией, только своё)

Контуры:

- `GET /contours` → `{ contours: Contour[], active: { contourId, until } }`
- `POST /contours` `{ name, slots?, windowDays?, schedule? }` → Contour (в конец)
- `PATCH /contours/:id` `{ name?, slots?, windowDays?, schedule?, position? }`
  (уменьшение `slots` ниже числа целей в слотах — разрешено; лишние цели
  остаются в слотах, клиент показывает перебор)
- `DELETE /contours/:id` → 204 / 409
- `PUT /contours/active` `{ contourId: string | null, until: ISO | null }`

Цели:

- `GET /goals?state=slot,bench` (по умолчанию `slot,bench`; `achieved` —
  отдельно, для «Истории») → `GoalView[]`, порядок: контур, затем `position`
- `GET /goals/:id` → `GoalView`
- `POST /goals` `{ contourId, title, why?, slot?: boolean }` → GoalView (`slot:
  true` = сразу в слот, 409 если слоты контура заняты)
- `PATCH /goals/:id` `{ title?, why?, contourId?, windowDays?: int | null,
  position? }`
- `POST /goals/:id/slot` `{ windowDays? }` → 409 `{ error: "slots_full" }`, если
  в контуре уже `slots` целей в слотах. Ставит `slottedAt = now`,
  `windowEndsAt = now + окно`.
- `POST /goals/:id/extend` → `windowEndsAt = max(now, windowEndsAt) + окно`
- `POST /goals/:id/bench` → `slottedAt = null`, `windowEndsAt = null`
- `POST /goals/:id/achieve` → `achievedAt = now`, `slottedAt = null`,
  `windowEndsAt = null`
- `POST /goals/:id/reopen` → `achievedAt = null` (на скамейку)
- `DELETE /goals/:id` → 204
- `PUT /goals/:id/tasks/:taskId` → связать (в конец); идемпотентно
- `DELETE /goals/:id/tasks/:taskId`
- `POST /goals/:id/tasks/:taskId/move` `{ beforeTaskId?, afterTaskId? }` —
  порядок внутри цели, по тем же правилам, что и `position` задач
  (`src/domain/position.ts`)
- `PUT` / `DELETE /goals/:id/ideas/:noteId`

`GoalView`:

```json
{
  "id": "...", "contourId": "...", "title": "...", "why": "..." ,
  "state": "slot", "slottedAt": "...", "windowDays": 7,
  "windowEndsAt": "...", "windowExpired": false, "achievedAt": null,
  "position": 1000, "createdAt": "...",
  "tasks": [{ "id": "...", "title": "...", "status": "pending",
              "projectId": "...", "projectName": "Дом", "focusedAt": null }],
  "nextStep": { "id": "...", "title": "...", "projectId": "...",
                "projectName": "...", "status": "pending", "focusedAt": null },
  "ideas": [{ "id": "...", "title": "...", "projectId": "...", "projectName": "..." }],
  "progress": { "done": 2, "total": 5 }
}
```

`windowDays` в представлении — **действующее** окно (своё или контура).

Рабочий набор:

- `POST /tasks/:id/focus` принимает необязательное `{ contourId }`; без него —
  контур по умолчанию (первый). Задача, уже стоящая в наборе другого контура,
  переносится в указанный (`focusedAt` не меняется).
- `GET /focus?contourId=...` — набор одного контура; без параметра — все (как
  раньше, для совместимости), в каждой задаче есть `focusContourId`.

## MCP и skill

- `list_tasks` / `get_task` отдают `goals` задачи.
- Новые инструменты: `list_contours`, `list_goals` (фильтр по состоянию),
  `get_goal`, `create_goal`, `update_goal` (поля + действие `slot | bench |
  extend | achieve | reopen`), `link_goal_task` / `unlink_goal_task`.
- `list_notes` — остаётся (совместимость), описание: «идеи проекта»; добавить
  синоним `list_ideas`.
- `SKILL.md`: что такое цели, контуры и идеи; **правило проверок** —
  проверка нужна, если поведение подтверждается только на устройстве, в
  реальном мире или со временем (UI на телефоне, виджет, гео, уведомления); не
  нужна, если изменение покрыто тестами, которые агент сам прогнал, или не
  меняет поведения (рефакторинг, документация, CI). Проверка — **не новая
  задача**, а пункт чек-листа в открытой задаче-сборнике проекта, чьё название
  начинается с «Проверить» (нет такой — создать «Проверить на телефоне»). Пункт
  называет, что проверить и к чему относится (задача, релиз).

## Правила интерфейса (поведение; вид — в спецификации дизайна)

- **Корона** на задаче, у которой `goals` не пусты: яркая, если хоть одна цель из
  активного контура, иначе приглушённая. Несколько целей — одна корона,
  названия целей — по нажатию / в редакторе.
- **Тёплый возраст** (`isStaleAge`) — только у задач из рабочего набора и задач
  с короной. Остальные — серый возраст, как сейчас при свежих.
- **Блок целей** сверху экрана «Работа» и в виджете: цели в слотах активного
  контура — название, «зачем», следующий шаг (нажатие — открыть задачу /
  взять в работу), прогресс, конец окна. Истёкшее окно — вопрос «оставить
  (продлить) / на скамейку / достигнута». Цели других контуров — одной
  свёрнутой строкой под блоком.
- **Рабочий набор** экрана «Работа» — набор **активного** контура; переключатель
  контура — в шапке «Работы» (и «Планирования»).
- **Дуэль**: при взятии в работу задачи, у которой нет целей активного контура,
  если у активного контура есть цели в слотах со следующим шагом, которого ещё
  нет в наборе, — экран выбора: эта задача против шага цели (с «зачем»). Выбор
  за человеком: «беру шаг цели» (в набор идёт шаг) или «всё равно эту». Задача
  с короной активного контура дуэли не вызывает.
- **Экран целей** (из «Планирования»): контуры вкладками; слоты (занято/всего),
  скамейка, создание и правка цели, привязка задач (выбор по всем проектам,
  поиск) и идей, порядок задач в цели, «достигнута».
- **Редактор задачи**: раздел «Цели» — к каким целям задача привязана, добавить/
  убрать.
- **Идеи**: «Заметки» везде переименовываются в «Идеи»; у идеи —
  «Сделать задачей» и «Связать с целью»; вид — заметнее нынешних заметок.
- **История**: раздел «Достигнутые цели» (название, когда достигнута, сколько
  задач закрыто).
- **Настройки**: контуры — название, слоты, окно, расписание, порядок,
  удаление.
- Записи целей и контуров — **только онлайн** в этой итерации (без офлайн-
  очереди); чтение — через кэш чтения, как доска.
