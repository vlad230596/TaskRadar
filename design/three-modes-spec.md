# TaskRadar — три режима: спецификация интерфейса

Документ-контракт для реализации (итерации F11–F13). Принят 21.09.2026 после
первой живой проверки диктовки на телефоне.

Эталон — статичные страницы рядом: [`reference/index.html`](reference/index.html),
по файлу на экран. Это не иллюстрации, а **источник размеров и цветов**: у
каждого элемента там проставлены точные px и hex. Кликабельная версия тех же
экранов — на дизайн-канве <https://claude.ai/artifact/AadcSh84MyrzouRGueYMyo>.

## Зачем это

Жалобы, из которых всё выросло (телефон, 18–21 сентября):

1. **Поля ввода мелкие** — в композере видно два-три слова, продиктованную фразу
   нельзя ни прочитать, ни поправить.
2. **Диктовка запускается не с первого раза**, и непонятно, тап это или
   удержание.
3. Приложение показывает всё сразу: при пятнадцати проектах это дорого по
   вниманию.

Ответ на третье — три режима, между которыми приложение переключается целиком
(идея «экономии мыслетоплива»: на экране только то, что требует решения сейчас):

| Режим | Показывает | Прячет |
|---|---|---|
| **Планирование** | все проекты, возраст, текущую задачу | закрытое, всё, что не требует решения |
| **Работа** | 2–5 задач набора, одну крупно | остальные проекты целиком |
| **История** | закрытое и залежавшееся, графику | очередь |

Переключение: нижняя панель на телефоне, левый рельс на десктопе. Приложение
открывается в том режиме, в котором его закрыли.

## Решения по данным

### 1. Журнал событий задачи — новая таблица `task_events`

Возраст и «последнее движение» считаются из `createdAt`/`updatedAt`, а
«сколько провисела в blocked» — нет. Поэтому журнал, по строке на каждый
переход:

```prisma
model TaskEvent {
  id        String      @id @default(cuid())
  taskId    String
  task      Task        @relation(fields: [taskId], references: [id], onDelete: Cascade)
  kind      TaskEventKind        // created | status | focused | unfocused
  fromStatus TaskStatus?
  toStatus   TaskStatus?
  at        DateTime    @default(now())

  @@index([taskId, at])
  @@map("task_events")
}
```

- Пишется в той же транзакции, что и изменение задачи, — иначе журнал врёт.
- Миграция проставляет существующим задачам по одному событию `created` с их
  `createdAt`: без этого «жизнь задачи» у одиннадцати существующих задач
  пустая.
- Удаление задачи уносит события (`Cascade`): это история задачи, а не аудит.

### 2. Набор «в работе» — поле `Task.focusedAt DateTime?`

Набор — серверный, а не локальный: он собирается на десктопе, а
отрабатывается с телефона. Порядок в наборе — по `focusedAt`.

Ограничение «не больше пяти» — правило экрана, а не базы: сервер не обязан
знать, почему пять.

### 3. Значок проекта — вычисляется, поля в базе нет

Буква — первая буква имени, цвет — стабильный хеш имени в палитру из шести
(см. ниже). Причина: поле означало бы UI выбора цвета, миграцию и ещё одно
решение при заведении проекта — то есть трату того самого мыслетоплива. Если
после жизни с этим захочется свой цвет — добавим поле тогда, хеш станет
значением по умолчанию.

## Язык интерфейса

Цвета (из иконки приложения, `design/icon/taskradar-icon.svg`):

| Роль | Hex |
|---|---|
| фон | `#F3F3F7` |
| карточка | `#FFFFFF` |
| чернила / первичная кнопка | `#1B2050` |
| индиго (выделение, **и только голос** среди кнопок) | `#4A56BE` |
| индиго-заливка (активная вкладка, чип проекта) | `#E6E8F7` |
| текст второго плана | `#61637E` |
| линия | `#DEDEE8` |
| «сделано» | `#2A6B4E` |
| «ждёт» / «залежалось» (текст `#8A5A0B`, заливка `#FDF7EE`, точка `#E0A03C`) | — |
| тревога (счётчик песочницы) | `#B3341F` |
| тёмный фон диктовки | `#14183C` |

Шрифты: **Golos Text** (интерфейс, 400/500/600/700) и **Unbounded** (600/700 —
только крупные числа, названия режимов и заголовки экранов). Оба с кириллицей,
оба OFL. Класть в `app/assets/fonts` и объявлять в `pubspec.yaml` — не тянуть
из сети: приложение обязано открываться без неё.

Правила, которые важнее конкретных пикселей:

- **Микрофон живёт в одном месте.** На телефоне — четвёртая кнопка нижней
  панели справа, подпись «Голос»; на подэкранах — индиговый квадрат 56×56 в
  правом нижнем углу; на десктопе — низ левого рельса. Индиговым не красится
  больше ни одна кнопка.
- **Мишень не меньше 44 px**, у микрофона и «Готово» — больше.
- **Плашка возраста не переносится и не сжимается** (`нет переносов`,
  `flex-shrink: 0` в эталоне) — на телефоне это уже ломалось.
- **Меньше текста, больше графики**: статусы — точки, возраст — число + цвет,
  доля времени в статусе — полоска.
- Числа — табличными цифрами, чтобы не дёргались.

## Диктовка: что именно меняется

Сейчас (`app/lib/widgets/dictation.dart`) кнопка различает удержание и тап:
короче 350 мс — «замок», дольше — «отпустите, чтобы распознать». Два режима у
одного нажатия и есть причина жалобы №2.

Становится так:

1. Тап по микрофону открывает экран диктовки. **Запись стартует при открытии**,
   без второго действия.
2. Удержания нет вообще. Закончить — «Готово» во всю ширину (76 px) или тап по
   области текста.
3. Пока модель грузится, экран уже открыт и говорит, что происходит; звук
   пишется с первого кадра, а не после готовности модели.
4. Распознанное появляется кеглем 25 px на пол-экрана — правится сразу.
5. Куда уедет текст, видно сверху («Песочница» / имя проекта / «в задачу»), и
   это переключается до нажатия «Готово».

Отдельно: **разобраться, нет ли настоящей гонки** в
`app/lib/providers/voice_providers.dart` (разрешение микрофона + загрузка весов
против первого нажатия). Новый жест её маскирует, но не лечит; если гонка есть,
её чинить, а не оставлять на «теперь и так не воспроизводится».

## Порядок работ

- **F11 — бэкенд**: `task_events`, `Task.focusedAt`, роуты набора и истории.
- **F12 — клиент, оболочка и планирование**: тема, три режима и навигация,
  диктовка, экраны планирования (список/плитки, проект, задача, песочница).
- **F13 — клиент, работа и история**: набор, экран работы, экран истории на
  данных F11.
