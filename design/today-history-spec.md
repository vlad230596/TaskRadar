## 1. Настроение: где синий

Владельцу нравится экран диктовки и тёмно-синий градиент целей. Правило целей
(«важное — на тёмно-синем») сохраняется и **расширяется ровно на одно
место — пересмотр**:

- **Пересмотр — тёмный, как диктовка.** Это раз в неделю и это момент выбора,
  а не список: полноэкранный поток на `voiceBackground`, карточки
  `goalRaised`, белые главные кнопки. Вход в него — карточка с градиентом цели
  (`goalStart → goalEnd`) наверху «Сделано». Лист «Следом» — тоже тёмный (это
  та же семья, что диктовка и редактор: короткий ввод «что дальше»).
- **«Сегодня» — светлое.** Это рабочий список дня, его смотрят десятки раз; он
  не должен перекрикивать блок целей. Белая карточка, плотные строки,
  тёмно-синим в нём остаются только короны.
- **«С прошлых дней» — тёплое, а не красное.** Семья «ждёт» (`waitingFill` /
  `waitingLine` / `waitingInk`): хвост — приглашение разобрать, не тревога.
  Красного (`alarm`) нет нигде в этой итерации — ни у хвоста, ни у ритма, ни у
  пропущенного пересмотра.
- **Ритм — приглушённый.** Метка `muted` без заливки. Решения по ритму
  принимаются на пересмотре (там он на тёмном и заметен).
- Золото — по-прежнему **только корона**. Индиго-кнопка — только микрофон.

## 3. Метка даты (везде одна функция)

`formatTaskDate(remindAt, remindTime, today)` — заменяет `formatReminderDate` +
«пора · DD.MM» в строках. Слово «напоминание» в интерфейсе больше не звучит
(кроме «Напоминания по месту» — это другое).

| Дата задачи | Метка | Цвет | Пример |
|---|---|---|---|
| < сегодня, 1 день | «вчера» | `dateOverdue` | вчера |
| < сегодня, ≥ 2 дней | «N дн. назад» | `dateOverdue` | 3 дн. назад |
| = сегодня | «сегодня» (+ « · 15:00») | `dateToday` 700 | сегодня · 15:00 |
| = завтра | «завтра» (+ время) | `dateSoon` | завтра · 9:30 |
| через 2–6 дней | «дн DD.MM» | `dateSoon` | сб 28.11 |
| через ≥ 7 дней, этот год | «D мес» | `dateSoon` | 25 фев |
| другой год | «D мес YYYY» | `dateSoon` | 3 янв 2027 |

Месяцы: янв, фев, мар, апр, мая, июн, июл, авг, сен, окт, ноя, дек. Дни:
пн вт ср чт пт сб вс (строчные). Время — «9:30», без ведущего нуля.

На строке метка стоит во второй строке под заголовком: значок календаря 13 +
метка `dateLabel`. У текущей задачи — «→ следующая · сегодня». У блокера —
«ждёт 2 д · проверить сб 28.11» (дата у блокера = «когда проверить»,
решение 6). У сделанной метки нет.

## 4. Работа

Эталоны: `Focus-Today.html`, `Focus-Tail.html`, `Today-States.html`,
`Desk-Focus-Today.html`.

Порядок сверху вниз (контракт): шапка → блок целей (+ строка других
контуров) → **«С прошлых дней»** → **«Сегодня»** → крупная карточка набора →
«Дальше». Экран прокручивается целиком, как сейчас. Пул по-прежнему
открывается при пустом наборе («Набор пуст · Собрать набор») — ниже
«Сегодня»; дуэли «Сегодня» не вызывает.

   сначала все задачи со временем (по времени), потом без времени по скоупу.
   Но интерфейс группирует по скоупам — задача «15:00 Встретить курьера» из
   «Дома» либо вылезает над подзаголовком «РАБОТА», либо порядок клиента
   расходится с сервером. **Предложение**: клиент группирует по скоупам, внутри
   скоупа — время, потом проект/позиция (как нарисовано); порядок `/today`
   остаётся для MCP. Если владелец хочет «время важнее скоупа» — отдельная
   группа «ПО ВРЕМЕНИ» сверху. До ответа — как нарисовано.
2. **Задача в двух блоках «Работы».** Шаг цели с датой «сегодня» виден и в
   блоке целей, и в «Сегодня»; задача из рабочего набора с датой «сегодня» —
   и в «Сегодня», и в крупной карточке/«Дальше». Недавний коммит убрал как раз
   такой повтор (шаг цели в наборе). **Предложение**: в «Сегодня» показывать
   всё (это список дня, его счётчик должен сходиться), но строку задачи из
   набора помечать точкой «в работе», а в «Дальше» такую задачу **не**
   повторять. Шаг цели — дублировать (блок целей отвечает на другой вопрос).
   Нужно решение владельца.
3. **«Снять» на шаге 2 пересмотра не определено.** В решениях: «оставить / в
   стопку / снять». «В стопку» понятно (из набора, без даты). «Снять» может
   значить: удалить задачу; закрыть без счёта (статуса «отменена» нет и не
   будет); убрать только из набора, оставив дату. **Предложение**: «Снять» =
   удалить задачу (с отменой в снекбаре 6 с) — «больше не собираюсь».
   Закрытие было бы враньём в «Сделано». Нужен ответ владельца; до ответа
   кнопка — «Удалить» с подтверждением-снекбаром.
4. **Время при быстрых действиях.** «Сегодня»/«Завтра» в строке, «Сегодня» и
   «Все в сегодня» в хвосте, диктовка «на завтра» — контракт не говорит, что
   с `remindTime`. Перенос «Встретить курьера 15:00» на завтра с сохранённым
   временем даст пуш в 15:00 — возможно, неверный; перенос хвоста «на
   сегодня» со временем 9:00 при 14:00 сейчас — пуш в прошлом. **Предложение**:
   быстрые действия снимают время (дата без времени); время ставится только
   в редакторе. Лист даты (выбор дня) время **сохраняет** (там видно
   «Время 15:00 сохранится»).
5. **Задачи без даты, закрытые сегодня, в счётчик не входят.** По контракту
   `doneToday` требует дату ≤ сегодня. Закрыл из набора задачу без даты —
   «3 из 7» не меняется. Это честно («Сегодня» = назначенное), но может
   удивить. Предлагаю оставить как есть и **не** показывать такие задачи в
   «Сегодня» — они видны в «Сделано». Только подтвердить.
6. **«Вернуть» без сети.** `POST /tasks/:id/reopen` — новый маршрут; в
   офлайн-очереди его нет. Обычный PATCH статуса по контракту тоже снимает
   закрытие, но не возвращает в рабочий набор. **Предложение**: офлайн —
   кнопка неактивна («Вернуть можно с сетью»); либо добавить `reopen` в
   очередь как отдельный тип операции. До ответа — неактивна.
7. **Виджет не знает про хвост.** Если «Сегодня» пусто, а хвост из 14 задач,
   строка виджета скрыта (M = 0) — и виджет молчит про главное. **Предложение**:
   при непустом хвосте строка видна: «Сегодня 0 из 0 · с прошлых дней 14».
   Нужен счётчик хвоста в снимке виджета (клиент его уже считает).
8. **Подсказка про свайп.** «Сегодня/Завтра» в строке проекта — свайп и
   долгое нажатие; обе вещи невидимы. **Предложение**: один раз (локально) при
   первом открытии проекта после обновления — строка-подсказка над списком
   «Свайп влево по задаче — «Сегодня» или «Завтра»» с крестиком. Не
   поведение, но в контракте «точное место — спецификация», поэтому
   отмечаю.
9. **Пересмотр без сети.** Контракт: шаги действуют существующими маршрутами
   (многие идут через офлайн-очередь), но `/reviews/draft` и `POST /reviews`
   — только онлайн. Предлагаю начинать пересмотр только с сетью (карточка:
   «нужна сеть»), а если сеть пропала посередине — шаги продолжают работать
   через очередь, «Записать» ждёт сеть с подписью «запишем, когда будет
   сеть» и повторяет сам. Это требует, чтобы `POST /reviews` был
   идемпотентен на период (повтор не создаёт вторую запись) — проверить в
   бэкенде.
