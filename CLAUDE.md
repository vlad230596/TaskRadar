# TaskRadar — правила для агентов

## Релизы: номер версии

Номер следующего релиза **не выбирается руками** — его считает workflow
`Release TaskRadar` (`.github/workflows/release.yml`) по тегам на `origin`.

- Запуск: `gh workflow run release.yml --ref main -f bump=minor`
  (`patch` — только исправления; `minor` — новые возможности, по умолчанию;
  `major` — несовместимые изменения API или данных).
- Поле `version` не передавать. Оно для редких случаев, когда владелец сам
  назвал точный номер; workflow всё равно откажет, если номер не новее
  последнего тега.
- Какой номер получился — в логе шага `Validate release input` и в summary
  запуска («Releasing X.Y.Z (latest was …)»). Его и называть владельцу.
- Если нужно узнать текущую версию самому — только с удалённого репозитория:
  `git ls-remote --tags --refs origin` или `gh release list`. **Локальным
  `git tag` не верить**: теги создаёт CI, и в локальной копии их может не быть
  (так 15.10.2026 релиз был запущен с уже занятым номером `0.14.0`).
- APK собирается отдельно (`app-release.yml`) из **уже существующего** тега —
  того, что только что создал релиз; номер брать из summary релиза или с
  `origin`, не придумывать.

## MCP для агентов и skill

- MCP-сервер — `backend/src/mcp/taskradarMcp.ts` (эндпоинт `/mcp`, токен из
  настроек приложения). Подключается у владельца в **user-скоупе**
  (`claude mcp add --scope user ...`), не в local: local десктоп-приложение не
  поднимало.
- Skill, который учит агентов в любом проекте понимать «мои задачи», —
  `agent-skill/taskradar/` (+ запасной клиент `mcp_call.py`). В
  `~/.claude/skills` он подключён ссылкой: `scripts/install-agent-skill.ps1`.
- Меняешь набор или поведение инструментов MCP — обнови `SKILL.md` в том же
  коммите. Новое поле задачи в приложении (как картинки, чек-лист, место) —
  проверь, видно ли оно через MCP.

## Перед релизом

- Полный прогон тестов приложения включает `test/zz_capture_*` — это тоже
  тесты, и CI их гоняет; падение там — не «артефакт съёмки».
- Сборка под Windows в CI идёт на более новой Visual Studio, чем локально:
  ошибки компилятора в нативных плагинах видны только там.
- Деплой и миграции — `DEPLOYMENT.md`.
