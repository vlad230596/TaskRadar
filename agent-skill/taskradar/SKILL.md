# TaskRadar

TaskRadar — личный трекер владельца. Доступ к нему — MCP-сервер `taskradar` (https://task-radar.duckdns.org:8443/mcp, Bearer-токен из настроек приложения; подключён глобально — в Claude Code в user-скоупе, в Codex в `~/.codex/config.toml`).
Инструменты: `list_projects`, `list_tasks`, `get_task`, `get_picture`, `list_ideas` (= старое `list_notes`), `list_inbox`, `search`, `create_task`, `update_task`, `move_task`, `list_contours`, `list_goals`, `get_goal`, `create_goal`, `update_goal`, `link_goal_task`, `unlink_goal_task`.

Этот skill лежит в репозитории TaskRadar (`agent-skill/taskradar/`, https://github.com/vlad230596/TaskRadar) и подключён в `~/.claude/skills` и `~/.codex/skills` ссылкой (`scripts/install-agent-skill.ps1`). Меняешь инструменты MCP — поправь и этот файл.

## Если инструментов `taskradar` нет в сессии

В Claude Code сначала `ToolSearch` с запросом `+taskradar` — сервер мог ещё подключаться.
Если инструментов нет — тот же сервер через запасной клиент `mcp_call.py` из папки этого skill (`~/.claude/skills/taskradar/` или `~/.codex/skills/taskradar/`). Токен он берёт сам — из `TASKRADAR_TOKEN` или конфига Claude Code; не выводи его:

```bash
python -I -X utf8 <папка skill>/mcp_call.py tools
python -I -X utf8 <папка skill>/mcp_call.py list_tasks '{"status":["pending","blocked"]}'
python -I -X utf8 <папка skill>/mcp_call.py get_task '{"taskId":"..."}' --images DIR
```

С `--images DIR` картинки из ответа сохраняются в DIR файлами — открой и посмотри их. Скажи владельцу одной строкой, что MCP в сессии не поднялся и ты пошёл через запасной клиент.

## Как отвечать

- Статусы: `pending` — в работе, `blocked` — заблокирована, `done` — сделана. «Что в работе / мои задачи» = `pending` + `blocked`. `inWorkingSet` — задачи, которые владелец отобрал «делать сейчас»; `workingSetContourId` — в наборе какого контура.
- `list_tasks` отдаёт `projectId`, не имя — имена бери из `list_projects` (там же скоупы: «Основной», «Мои проекты», «Работа»).
- Группируй по скоупу → проекту, в порядке выдачи (это приоритет владельца). `current: true` — текущая задача проекта, помечай ★. В списке `pictures: N` — у задачи есть картинки, `checklist: {done,total}` — прогресс чек-листа.
- Если владелец в репозитории, который совпадает с проектом TaskRadar по имени (папка `CashFlow` → проект CashFlow), и спросил «мои задачи» без уточнения — покажи сначала задачи этого проекта, затем предложи остальные.
- Берёшься за задачу — сначала `get_task`: полный текст, чек-лист, журнал и картинки (обычно скриншоты бага — смотри их). Первые 5 картинок приходят в ответе, остальные — `get_picture` по id.

## Цели, контуры, идеи

- **Цель** — результат, который владелец сейчас продвигает. Состояния: `slot` (в слоте, с окном до `windowEndsAt`), `bench` (скамейка), `achieved`. У цели есть `why` и **следующий шаг** (`nextStep`) — первая `pending`-задача в порядке цели; `null` — шагов нет, цель надо обсудить. Задачи цели — из любых проектов.
- **Контур** — набор слотов («Работа», «Личное»), действующий в своё время (`schedule`). У каждого контура свой рабочий набор. Первый в `list_contours` — контур по умолчанию.
- У задачи `goals` — цели (не достигнутые), которым она служит: это **корона**. Спросили «что делать / что важно» — начинай с `list_goals` (слоты и их `nextStep`), потом остальное. `windowExpired: true` — окно цели истекло: скажи владельцу, решает он (продлить / на скамейку / достигнута).
- **Идея** (в старых названиях — заметка) — мысль, которая может стать задачей; без статуса и возраста. `list_ideas` по проекту.
- Цели — приоритеты владельца: `create_goal`, `action: "achieve"` и перенос между слотом и скамейкой — только по его просьбе. `link_goal_task` — когда он связал задачу с целью словами или подтвердил предложение.

## Проверки на устройстве

Проверка нужна, когда поведение подтверждается только на устройстве, в реальном мире или со временем: UI на телефоне, виджет, гео, уведомления. Не нужна, когда изменение покрыто тестами, которые ты сам прогнал, или не меняет поведения (рефакторинг, документация, CI).

Проверка — **пункт чек-листа**, а не новая задача: в открытой задаче-сборнике проекта, чьё название начинается с «Проверить» (`list_tasks` с `query: "Проверить"`; нет такой — создай «Проверить на телефоне»). Добавь пункт через `update_task` с полным чек-листом (id старых пунктов сохраняй). Пункт называет, что проверить и к чему относится: «Виджет: шаг цели открывает задачу (релиз 0.15)».

## Изменения

- `create_task`, `update_task`, `move_task` меняют данные владельца: делай их, когда он об этом попросил, или подтверди одной фразой, если инициатива твоя (например, follow-up по итогам работы).
- Закрытие — `update_task` со `status: "done"` (пишется в журнал, задача выходит из рабочего набора). Рабочий набор — `update_task` с `inWorkingSet`.
- Чек-лист в `update_task` передаётся целиком: сохраняй `id` пунктов из `get_task`, у новых пунктов `id` не нужен.
- Удаления через MCP нет — не обходить.
